# Quarry Turtle v1.1 — automatic chest recovery

A self-contained CC: Tweaked mining-turtle program. Default footprint: 16 × 16; default depth: 64 blocks below the turtle's starting block. Three layers are cleared per horizontal pass (above, centre, below). Partial final bands stay within the chosen depth.

## Install with Pastebin

1. Open `quarry.lua` from this download, copy its complete contents into a new Pastebin paste, and save it. No Pastebin account credentials are needed by this program.
2. On a mining turtle (diamond pickaxe upgrade), run `pastebin get YOUR_PASTE_ID quarry`.
3. Place the turtle at the near-left corner, facing into the quarry. The quarry extends 16 blocks forward and 16 blocks to its right, including the column beneath it. Place a vanilla chest directly behind the turtle at the same height. Starting Y is the turtle's own block; the first mined layer is immediately below it.
4. Put several stacks of coal or charcoal into the chest's first slots. Leave plenty of output capacity or drain the chest into storage.
5. Run `quarry config`, then `edit quarry-data/config`. For a first trial, set width and length to 3 and depth to 6. Keep the Lua table syntax generated by the program.
6. Run `quarry init`, then `quarry` to start. Dimensions cannot change after init.
7. For automatic restart after loading, run `edit startup.lua` and enter:

```lua
shell.run('quarry')
```

If you already have a startup program, add this deliberately rather than replacing it. The optional supplied startup.lua checks for an initialized job first. Keep the entire quarry chunk area and starting chest loaded; this program cannot load chunks itself.

## Controls

| Command | Effect |
| --- | --- |
| `quarry config` | Create/show the config path before initialization |
| `quarry init` | Record origin and facing; does not move |
| `quarry` | Start or resume the saved job |
| `quarry status` | Show phase, local position, fuel and pending action |
| `quarry continue` | Resume a deliberate pause after fixing its cause |
| `quarry return` | Request a return when launching a saved work phase |
| `quarry recover before` | Optional manual override before automatic recovery starts |
| `quarry recover after` | Optional manual override before automatic recovery starts |

The turtle console is occupied while mining. Hold Ctrl+T to stop; launch `quarry return` afterwards. Ctrl+T can interrupt an action; the next launch automatically homes to the chest before processing the return request. Never pick up, manually move or rotate the turtle during a job.

## Configuration

- `width`, `length`, `depth`: positive integers; 16, 16, 64 by default. Finite depth makes quarry boundaries unambiguous. Bedrock or another protected/unbreakable block stops the job and triggers a return attempt.
- `trash`: exact item/block IDs mapped to true. Includes common vanilla dirt, stone, gravel, cobblestone, deepslate and similar filler. Unknown modded IDs are kept. Ores often drop a different item ID: item disposal uses the drop ID, vein classification uses the block ID.
- `discardTrash`: true by default. Drops listed items only down into inspected empty space without a peripheral. Drops are world entities, not permanently deleted, and may be recollected. Set false to keep everything and unload it into the chest. Grass blocks usually drop dirt, which is also listed.
- `fuel`: coal and charcoal only. Valuable fuel items are not automatically burned. Add exact item IDs deliberately.
- `fuelMargin`: 64 extra movement fuel above the recovery budget. Work now reserves approximately three times the return-route length, plus this margin, to cover a wrong recovery trial and the correct return.
- `fuelTarget`: 2000 desired fuel at the chest; automatically increased for the outbound and return trip. A low fuel limit may require a smaller quarry.
- `retries`: 12 bounded movement attempts for falling blocks or entities. No mob attacks.
- `veinLimit`: 128 visited unknown blocks per search; `veinDepth`: 24 recursion levels. Searches follow face-connected nontrash blocks and stay inside the quarry footprint and finite depth. These limits prevent huge modded rock deposits from monopolizing a search; remaining blocks are mined by subsequent quarry passes.
- `protected`: bedrock, chests, barrels, spawners and end portal frames by default. Detected peripherals, turtles and shulker boxes are also protected. Add modded machines and structures by exact ID; not every modded block entity exposes a peripheral, so automatic protection is not exhaustive.

## Refueling and returning

Uses allowed fuel from its own inventory first. Before each work move it checks fuel against approximately three times its actual breadcrumb return route, including vein detours, plus a safety margin. Depth alone is not sufficient for this calculation.

On an ordinary service trip it retraces saved adjacent positions to the origin, unloads, checks chest fuel, and retraces the outbound path to continue. At band completion it stays at the origin before starting the next band, keeping route lengths bounded.

Native `turtle.suck` cannot select a particular chest slot. Without requiring modems, this program scans chest stacks into spare turtle slots, consumes allowed fuel, and returns nonfuel. It can inspect at most 16 nonfuel stacks per attempt. Keep coal in early chest slots; if necessary move it to the first slot and run `quarry` again. A full or missing chest pauses safely at the dock.

## Resume and automatic chest recovery

Progress, vein search, service trip, pose and route are saved after actions in alternating checkpoints. Normal saved progress resumes automatically with the startup program. If a shutdown leaves a move or turn unfinished in the checkpoint, the program automatically tries the two possible poses. No GPS, modems or extra computers are required.

For each pose hypothesis it retraces the recorded adjacent route toward the predicted origin. It only attempts to move through air or passable fluids during recovery: **it never digs while its pose is uncertain**. If a trial is blocked or reaches a predicted origin without the chest, it tries the remaining hypothesis. Fuel readings help choose which movement hypothesis to try first, but do not replace the chest check; unlimited-fuel mode is supported too.

At the predicted origin it faces the expected chest side and checks for an inventory matching the original peripheral type and slot capacity recorded at init. Finding the chest reestablishes the origin and facing. It unloads/refuels, resets the interrupted vein search, and restarts the saved quarry cell. Some work may be repeated; already removed blocks are harmless to revisit. A saved user-requested return or issue pause remains a pause at the chest.

**The starting chest must remain the only matching inventory in the area recovery could reach.** Keep other matching chests away from the quarry and starting corner. Type and capacity are a cheap landmark signature, not a globally unique identity. Without GPS or a uniquely recognizable landmark, identical chests cannot be distinguished reliably. Keep the original chest in place, use a vanilla chest, and keep the quarry and dock loaded. Initialization now requires the chest behind the turtle.

The ordinary fuel reserve includes approximately three times the saved return-route length plus a safety margin. A single interrupted action can require a wrong trial and retracing before the correct return. Multiple additional interruptions during recovery may require more fuel. Recovery actions and pose hypotheses are also checkpointed, allowing another reboot to resume recovery. If insufficient fuel remains, it waits safely with its hypotheses saved.

If no candidate reaches the chest, recovery reports the problem and retains the updated hypotheses for retry. Replace a missing chest at its original position, restore chunk loading or clear a blocked route, then run `quarry` again. Unlike ordinary returns, recovery will not dig through fallen gravel or newly placed blocks. These exceptional failures can still require intervention; this is not a guarantee of recovery after arbitrary world changes, manual relocation, storage corruption or a server rollback.

`quarry recover before|after` remains an optional manual override while the original pending action is still saved, before automatic recovery begins. Routine interrupted actions do not require these commands or a player to confirm the underground position. Never manually move or turn a turtle during recovery.

Protected blocks, digging failures and other known errors trigger an ordinary return attempt and pause. Fluids are traversed when the turtle API permits it; no fluid sealing or bucket collection is included. Make a world backup before testing around builds or valuable terrain.

### Updating an existing v1 job

Replace only the `quarry` program on the turtle; keep `quarry-data` and its startup script. Prefer updating while the turtle is docked, so it can refuel for the larger recovery reserve before going back down. Do not run init again. Legacy jobs learn the chest signature on the next normal docking; an already interrupted legacy job can fall back to recognizing a vanilla chest/barrel during homing.

For a fresh job, use a new turtle or archive/remove `quarry-data` only after the old job is finished and the turtle has been positioned at the new origin.

## Validation

579 offline Lua 5.4 mock scenarios passed. Coverage includes completed 3 × 3 × 6 quarries with modded veins and depth/footprint checks; interruption offsets swept across mining, veins and return trips; interruptions before/after movement and turning; further interruptions during recovery; missing/restored chests; open-space wrong trials; unlimited fuel; insufficient recovery fuel; protected blocks; full chests; zero fuel; and no digging during uncertain recovery.

The source uses CC: Tweaked's documented turtle, peripheral, filesystem and textutils APIs. It has not been run in Minecraft or your Craftopia pack; start with the small trial above. The mocks do not simulate every mod's block, inventory or chunk-persistence behaviour.

`test.lua` is the offline test harness, not a turtle program. Production logic is all in `quarry.lua`; there are no downloaded dependencies.
